# Offline library inventory comparison

Compare two saved `mtx status` captures after confirming they represent the
same library. This uses the existing mtx parser; it does not execute mtx, sg
utilities, robot inventory, a move, or a query.

```sh
python3 -m tapediag inventory-diff fixtures/v4/inventory-before.txt fixtures/v4/inventory-after.txt --library-id SYNTH-LIB
```

`--library-id` is a required caller-confirmed stable anonymous scope, not a
serial inferred from `/dev/sgN`. Different header device labels produce a
mapping warning. `--html OUTPUT.html` also writes an escaped, self-contained
view of the same evidence; JSON stays on stdout. `--execute` is refused before
input access. Exit 0 means comparison completed, even with changes/warnings;
exit 2 means invalid/refused input or local I/O failure.

Both captures need an mtx storage-changer header. Duplicate element identities
are refused, including a storage slot and IE port reusing one number. Truncated
counts/unrecognized element lines remain warnings. Files use the existing bounded
16 MiB regular-file reader. SG binary element-status responses and sg decoded
text are **not** accepted as mtx: SCSI element addresses and mtx logical slot
numbers must not be silently equated.

The `tapediag-inventory-diff-v1` result matches drive elements by drive number
and storage/IE elements by storage number. It reports occupancy, primary and
alternate tags, source-slot and storage/IE type changes. Missing elements are
`unobserved-after`; new entries are `newly-observed`. Neither claims hardware
removal/addition. Empty tags do not establish empty occupancy; full/empty comes
from the explicit captured state.

Unique matching tags changing location can produce `relocation_candidates`.
Both endpoints must appear in both captures. Duplicate tags or tags attached to
empty elements are listed in `ambiguous_tags` and excluded from candidates.
Primary and alternate tags share the ambiguity check. A tag match is only a
candidate association: two captures cannot prove the physical move, uniqueness
of real media, intervening operations or which application acted. No commands
or drive-to-`/dev` mapping are generated. Existing source-slot, duplicate-tag and
count consistency warnings remain visible. An empty source slot after a load is
normal; occupied IE says nothing about the door or sensors.

The synthetic before/after fixtures show cartridge SYNTH-V4-A at slot 1 then
at drive element 0 while slot 1 is empty. They are original invented text,
regenerated by `PYTHONPATH=. python3 scripts/generate-v4-fixtures.py`. Public
format reference: [mtx status documentation](https://github.com/mtx-org/mtx/blob/master/mtx/mtx.doc)
and [mtx manual](https://github.com/mtx-org/mtx/blob/master/mtx/mtx.1), checked
2026-10-20. [SMC public element-status proposal 08-066r0](https://www.t10.org/ftp/t10/document.08/08-066r0.pdf)
provides protocol context; no full robotics-health or current-standard conformance
claim is made. Candidate matching and ambiguity policy are original toolkit rules.

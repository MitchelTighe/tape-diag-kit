# Optional drive-owner lock adapter

This is an original DTA extension contract for coordinating with the application that owns a drive (for example, a hierarchical storage manager or backup server). It does not implement or describe any product's native admin commands. The implementation provides a vendor-neutral command-template seam with an injectable verifier; it was developed using synthetic inputs and public vendor references only. A site supplies and reviews its own adapter executable.

Without `[owner]`, DTA requires manual exclusive maintenance ownership and reports application acceptance as unverified. With `[owner]`, the first mutating step locks the configured drive/device; every subsequent zone/media/test gate requires a fresh proof that this run still owns the lock, the owner is idle, and no mounts are active or pending. Only after media return and complete fabric restoration may the final owner step unlock and verify visible/usable state. Known diagnostic or evidence failures deliberately retain ownership for operator review.

## Configuration contract

The commented `[owner]` block in `config.example.toml` is the template. `ssh`, `drive`, and `device` are locally supplied opaque identifiers; they must select precisely the same physical drive as ITDT/library identities. `lock_argv`, `unlock_argv`, and `verify_argv` are lists of argv data with an absolute reviewed executable. Supported placeholders are `{serial}`, `{manufacturer_serial}`, `{drive}`, `{device}`, `{run_id}`. Every template must bind `{serial}` and `{run_id}`. Shell snippets, shell metacharacters, environment expansion and unknown placeholders are rejected. DTA shell-quotes the complete generated argv for SSH; it never interpolates a shell program.

The adapter executable and its configuration are trusted operator code. Grammar validation cannot prove that an arbitrary executable is a safe ownership controller. Review its implementation, permissions, exact native-tool version, target mapping and state semantics before enabling it. A verifier must perform fresh owner queries; it must not replay a saved response or synthesize an optimistic state after a query error. DTA's built-in fake is explicitly synthetic and has no subprocess/network implementation.

The lock command must atomically acquire exclusive maintenance ownership for `run_id`, prevent new owner mounts/scheduling, and reject another run's lock. It must not break an active mount, unload production media, erase data, or force a release. The initial probe must show unlocked, usable and idle with no mounts; a pre-existing lock is refused so this run cannot accidentally release someone else's maintenance hold. Following the lock command, a new probe must confirm this run's lock and zero active/pending mounts before zoning can change.

The unlock command must release **only the same run's lock** and restore intended owner availability. It must reject a token mismatch and must not mount a cartridge itself. The final probe must report unlocked/usable. Production work may legitimately start after unlock, so the final probe may report a non-idle drive with mounts; this is never accepted during diagnostics.

Both native writes still require `--apply` and terminal serial confirmation, and both are durably journaled before dispatch. Write timeouts leave `pending`; DTA never replays an uncertain owner operation. The plan shows owner unlock last in rollback, after media return and fabric restoration in reverse order. No owner command is run by default, and no native product command spelling is invented here.

## Verifier JSON

Return process status zero and exactly one UTF-8 JSON object with **all and only** the following fields. This fictional example describes a locked, idle owner; the timestamp below is illustrative and will be refused as stale unless it is freshly generated by the adapter.

```json
{
  "schema": 1,
  "serial": "SYNTH-DRIVE-DTA",
  "manufacturer_serial": "SYNTH-PHYSICAL-DTA",
  "drive": "SYNTH_OWNER_DRIVE",
  "device": "SYNTH_OWNER_DEVICE",
  "locked": true,
  "lock_owner": "SYNTH-DEMO",
  "idle": true,
  "mounts": 0,
  "usable": true,
  "observed_at": "2026-10-18T00:00:00+00:00"
}
```

Use JSON booleans, an integer mount count including pending mounts, and RFC3339 time with a timezone. The observation must be within **60 seconds** of DTA's clock. Identity/resource values must exactly match config. When locked, `lock_owner` must equal the current `run_id`, `idle` must be true and `mounts` zero. When unlocked, `lock_owner` must be null and `usable` true. Unknown/stale state, skewed clocks, an absent field, another owner, or ambiguous resource mapping refuses the next mutation.

For a real integration, the locally reviewed verifier must map the owning application's device and drive states, in-flight/pending mounts, logical lock state and availability into this contract. Those mappings are intentionally **unspecified** here. Do not infer them from this synthetic JSON or silently treat a successful native command exit as proof of idle/usable state. The adapter must coordinate run ownership independently if the native tool has no ownership-token concept. That coordination is an integration requirement, not something DTA can establish from a generic command result.

## Synthetic reproduction

`fixtures/dta/config.owner.synthetic.toml` contains a wholly fictional enabled profile. The owner fake mutates in-memory booleans and token values only:

```sh
bin/dta --config fixtures/dta/config.owner.synthetic.toml --run-id SYNTH-DEMO
python3 scripts/verify-dta.py --owner-adapter \
  --scratch "$TASK_SCRATCH" \
  --output artifacts/dta/owner
```

`TASK_SCRATCH` is an existing empty directory chosen for synthetic rehearsal outputs. The first command plans only; the second runs an explicitly fake harness and records the entire plan, execution, audit and curated bundle. Owner tests cover every completed checkpoint, lost ownership immediately before the test, stale/busy/unknown proofs, known failed diagnostics retaining the lock, and uncertain lock/unlock writes. These checks do not validate any native product mapping or external owner service.
